# UK Flows are predicted out-of-fold, never in-sample

The model trains on every Exporter's Flows, including the UK's. But each UK Product–Market pair gets its Export Potential from a model that never saw that pair. We split UK pairs into 5 groups, keeping all years of a pair together; we train 5 models, each with all non-UK Flows plus 4/5 of UK pairs; and each pair is scored by the model that held it out. Features built from UK data (such as UK supply of a Product) are computed leaving out the target pair's Market. Training directly on UK Flows makes Export Potential copy Actual Exports, which shrinks every Export Gap to zero. Leaving the UK out entirely would lose the UK's general strengths. Scenarios for a pair use the same held-out model.

## Consequences

- **Held-out UK Flows still reach the fold models through other Exporters' demand features.** Leave-one-out removes each row's *own* Flow. A non-UK row's demand features (`log_demand_loo`, `high_income_share_loo`) leave out that row's Exporter, so they still include the UK's Flow to the same Market. For example, France's whisky exports to Japan carry Japan's whisky imports from everyone but France, UK whisky included, and fold model *k* trains on that row even when UK–Japan whisky is held out. What this means: no fold model can read a held-out pair's Actual Exports from that pair's own features or label, so the Export Gap is not shrunk by memorisation, which is what this decision protects. What remains is an indirect channel: where the UK supplies a large share of a Market's imports of a Product, the non-UK rows teach the model a demand level that includes UK sales, which can pull that pair's Export Potential slightly towards its Actual Exports. We accept it, because closing it would mean rebuilding every non-UK row's demand features without the UK, once per fold.
